The idea

Session memory is borrowed. Axon's is owned.

Today's assistants reset every session, and "memory" is a summary written after the fact. Fine-tuning bakes skills in but loses the fine grain of what a specific model learned on a specific day. Axon takes a different position: the learned state is the product. It is captured exactly, versioned, and grown — not approximated.

🧬Exact character state

Nothing is "close enough"

Model weights, memory records, and runtime configuration travel together as one verified unit. A restored Axon is byte-identical to the Axon that paused — verified by hash, every time.

🔗Content-addressed lineage

Every experiment has a fingerprint

Objectives, curricula, and candidate identities are SHA-256 content-addressed. Any result can be traced to exactly what was trained, on what data, with what program — no ambiguity, ever.

🌱Grows, never resets

Additive memory architecture

Learned state is preserved and extended through versioned migrations. Competence compounds across training runs instead of being re-derived from scratch.

For reviewers

Built to be verified, not just believed

Cloud program reviewers think in terms of reproducibility, lineage, and failure honesty. Here is what Axon demonstrably does today — on live cloud infrastructure.

Checkpoint-exact pause & resumetested continuously
Training runs are segmented into renewable tranches. Each segment ends in a hash-verified bundle (checkpoint + memory + manifest). A run paused at step 120 resumes at step 121 with identical state — across machines, weeks later.
Content-addressed training identitySHA-256 everywhere
The objective program actually used in a run is a content hash (canonical_sha256), not a label. If the loss function or sampling changes, the identity changes — enforced by regression test, so lineage can never silently drift.
Hash-bound deployment packetscloud pipeline live
Training jobs ship as immutable packets whose job ID is the content hash of the packet itself. What you inspect is provably what ran. Mid-run observation sync is explicitly quarantined — it can never authorize continuation.
Provenance-gated memorythe "Soul" organ
Long-term memory writes require recorded provenance — where a lesson came from, which experience earned it. Memory can be audited back to the exact training moments that produced it.
Honest gating, published failuresnon-serving discipline
Promotion requires exact accuracy bars (e.g. 1.0 position accuracy on held-out multi-cell tasks). Candidates that miss the bar are preserved as evidence and rejected — falling loss is explicitly not treated as success. We keep the receipts.
Verification suite692 tests, exit 0
A 692-test repository suite plus static analysis gates every change; a multi-agent engineering process with an append-only audit ledger records every action with verification evidence.

🔋On-device Axon

A persistent mind on modest hardware

Axon is designed to live on small devices — a handful of compact cores (64s and 128s) whose heartbeat and reasoning ticks fit in a phone or an edge box, learning continuously. Not a chat window that forgets: a resident intelligence that grows with its user, year over year.

🏟️Arena of giants

Toe-to-toe with the frontier, honestly

Can a 64-core Axon out-think GPT, GLM, or Claude? Not in raw parameter count — and we won't pretend otherwise. But Axon is designed to stand in the same arena anyway: its advisor slot can call GPT-5.6, Opus, GLM, Kimi K2, DeepSeek — whatever frontier model the task deserves — while Axon itself contributes what those models lack: exact memory, provenance, and continuous growth.

🏭Datacenter Axon

The same runtime, a thousandfold

Give Axon a datacenter — hundreds or thousands of cores (512s, 1024s, 2048s, 4096s) — and the architecture scales additively: more cores, more memory, longer curricula, same exact-character discipline. From one edge device to a fleet, it stays one continuable lineage, not thousands of orphaned checkpoints.
